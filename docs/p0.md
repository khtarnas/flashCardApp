# P0 — Must Have

These features are required for the app to be usable. The app isn't worth opening without them.

## Design Principles

- **Everything is mutable.** Modularity and separation of concerns above all. Design every component so it can be swapped, extended, or reconfigured without rewriting.

## Features

### 1. Deck Management
- Create a new deck (name, front language, back language)
- View list of all decks
- Edit deck name and languages
- Delete a deck (detaches cards, does not delete them — see D012)
- Deck names must be unique
- System-managed "All Cards" deck: shows every card, not deletable

### 2. Card Management
- Create a card within a deck (front text, back text) — plain text only (D011)
- View all cards in a deck
- Edit a card's front/back text
- Delete a card

### 3. Study Mode
- Start a study session for a deck
- Show card front, tap to reveal back
- Self-grade each card: "I know it", "I'm close", "No idea" (D008)
- Card ordering: sequential for P0, designed as swappable strategy (D009)
- Navigate through cards in the deck
- End study session: return to home screen (D010)

## Navigation

- Stack navigation (NavigationStack): Home → Deck → Cards → Study (D013)
- Portrait orientation only (D014)

## Data model requirements

- Deck entity with unique name, front language, back language
- Card entity with front text, back text
- Card-to-Deck relationship: many-to-many from the start (D003)
- Language enum with common languages + `.other` case
- "All Cards" is a system concept, not a regular Deck entity — represented as a synthetic view-model item (D026).

See `docs/data-model.md` for the full schema.
